## 第二次修复：爬虫配置版本号检查导致 JSON 修改不生效

### 问题
用户改了 crawler-rules.json 内容（加了"Feijiu网|四川"站点、改了名字），但版本号没变（还是1.0.2），应用没有反映变化。

### 根因
`initSeedData()` 第4步用版本号判断是否需要更新爬虫配置：
```js
const needUpdateRules = !initialized || seedVersion !== currentVersion || lastRulesVersion !== currentVersion;
```
用户上次已成功加载 v1.0.2，数据库里 `last_crawler_rules_version = '1.0.2'`，这次 JSON 版本号没变 → `needUpdateRules = false` → 跳过更新，数据库里的旧配置原封不动。

### 修复
将爬虫配置同步逻辑从版本号检查中分离：
- **外部 JSON 加载成功** → 每次启动都 `DB.clear('crawler_configs')` + 全量写入（不管版本号）
- **外部 JSON 加载失败 + 首次安装** → 用内置规则初始化
- **外部 JSON 加载失败 + 非首次** → 保留已有配置不动

核心原则：爬虫配置是运行时配置，应始终反映最新 JSON 文件内容，不依赖版本号。

## 第三次修复：爬虫认证流程完整实现

### 用户要求
各站点独立配置认证信息（Cookie/Token）+ fetchPage 自动携带 + 登录页检测提示

`crawlSite()` 的 try 块中存在三个严重问题：

2. `let customHeaders` 被声明了两次（第409行和第415行）
3. `const fetchResult` 被声明了两次 → 第一次调用结果被覆盖，且第二次没带认证头

### 修复内容

**js/crawler.js — fetchPage()**

- 登录页检测增强：`authConfig.required === true` 时，错误信息变更为 `返回登录页（Cookie失效或未提供，请去"设置→站点认证"填写）`

**js/crawler.js — crawlSite()**
- 完整重写认证流程：
  1. 解析 `config.auth` → `siteAuth`（站点认证要求）

  4. 构建 `customHeaders = { ...userAuth }`，传给 `fetchPage(url, customHeaders, siteAuth)`
  5. 只调用一次 fetchPage

**js/app.js — testAuth()**

- 改为解析 `config.auth` → 传入 `_testFetchPage` 第三参数

## 第四次修复：JSON 尾随逗号导致全盘失效（第三次踩同一个坑）

### 问题
用户加第4个站点"Feijiu网(四川省绵阳市废旧金属)"后，改的 JSON 内容完全没生效，应用仍显示旧的3个站点。

### 根因
`data/crawler-rules.json` 第67行尾随逗号 `},` 紧跟 `]`，JSON 标准不允许。`JSON.parse()` 抛 `SyntaxError` → `externalRules = null` → 回退到内置常量 CRAWLER_RULES（seed-data.js 第159-188行）。用户改的4个站点全白费，用的还是内置的3个旧站点。

### 附带问题
1. 用户把一整串真实 Cookie 塞进了 `auth.description` 字段（该字段是 UI 提示文字，不是放 Cookie 的地方）
2. 第4个站点配了 `type:"html"` 却写 `apiPath:"data.list"`（矛盾，HTML 类型应用 listSelector）

### 修复
- data/crawler-rules.json：去掉尾随逗号；Cookie 从 description 移除（改回说明文字）；第4个站点改为正确的 html + listSelector 配置；版本号升到 1.0.7

### 教训（已第三次踩坑）
**JSON 文件绝对不能有尾随逗号和注释。** 用户编辑 JSON 时容易犯这个错。考虑后续在代码层加一个 JSON 宽容解析（如 jsonc-parser）或在编辑后自动校验。
